# 重试失败请求

`dsh-session-tree` 通过 `/retry` 命令重试当前会话中的失败请求，使用 DSH 桌面端自带的斜杠命令入口，不占用输入框上方的常驻区域。

## 安装到桌面端

随整个插件一起安装，不单独安装 retry 功能。安装目录和包名见[仓库说明](../README.md#安装到桌面端)。

当前版本为 0.1.2。实现依据本机 `deepseek-harness` checkout 的接口；未通过运行中的 Cordis inspection 核对桌面端版本，实际恢复行为由使用者验收。需要宿主提供 `commands` 服务。

## 使用

1. 更新插件至 0.1.2，并完整重启 DSH，以移除旧 Client 面板并加载新的 Host 命令。
2. provider 的自动重试耗尽、请求进入手动等待后，在当前会话输入 `/retry` 并提交。该命令无需参数，也可从输入 `/` 后的命令列表中选择。
3. 命令确认重试已受理后，在原来的 turn/step 内重新请求模型。日志保留失败的 attempt，已完成的工具结果和消息不被删除，也不会新增“继续”消息。
4. 若再次失败并进入等待，可再次执行 `/retry`。原界面的“停止”可取消等待或正在执行的重试。
5. 没有等待的请求时，命令显示提示，不启动新轮次。

命令及结果由 DSH 记录为 `command/run`、`command/done`，不会进入模型消息历史。命令成功表示当前等待已释放，后续模型请求仍可能失败。

## 找不到命令或无法重试时

- **命令列表没有 `/retry`**：检查是否安装并启用了 0.1.2，完整重启 DSH，并查看插件行的激活报错。插件需要宿主的 `commands` 服务。
- **提示没有等待的失败请求**：当前没有被本插件接住且仍保持等待的失败请求。如果对话已经出现“本轮运行失败”并回到发送状态，这轮已关闭，当前版本无法恢复它。
- **仍显示旧面板**：确认更新安装的是 0.1.2，并完整退出、重启桌面端；仅刷新对话不能保证卸载旧模块。

模型恢复运行后，仍可能像正常执行一样发起新的工具调用。插件不会重新执行先前已完成的步骤，但不承诺外部副作用回滚或模型之后绝不再调用相同工具。

## 本版范围

- 插件必须在请求失败前已经启用。它通过 `agent/request-error` 在轮次关闭前等待手动操作，因此等待期间原界面仍可能显示“运行中”。
- 不恢复已写入 `turn/end` 的旧失败轮次，不实现 reroll，不伪造用户消息唤醒已结束的 Agent。
- 只接管 provider 正常重试策略允许的错误。`always` 模式保持自动重试；无策略的失败、普通工具错误和非 eligible 错误继续原有处理。
- 等待状态属于当前 Host 进程。切换视图不影响等待；退出/重启 Host、取消 Agent 或卸载插件会结束等待。重启后不能恢复旧请求。
- 当前请求的身份只可消费一次，过期或跨 Session 的 requestId 会被拒绝。不同 Session 的等待互不影响。每次 `/retry` 都针对提交时当前会话里等待的请求。

## 实现入口

- `src/retry/index.js`：`agent/request-error` 恢复监听、`/retry` 命令和工具注册，由根目录 Host 入口加载。
- `src/retry/recovery.js`：手动恢复状态、取消清理及请求身份校验。命令和工具共用 `runAction` 操作。
- `session_retry_failed_request`：同一 Host 操作的 deferred agent tool；先以 `action: "status"` 获取 `requestId`，再以 `action: "retry"` 提交。它不能让正在等待的 Agent 自己执行工具，需要另一个具备该工具的调用方。

0.1.2 移除常驻 Client 控件及其 Fetch 路由、状态流。Host 在等待期间保留原有 loop；实际请求和持久化仍由 dsh 自身负责。插件不增加 Session 事件类型，不修改历史文件。工具定义采用 deferred loading。

## 手动验收

- 更新并重启，确认旧面板消失，命令列表出现 `/retry`。
- 没有等待请求时执行 `/retry`，确认显示提示且不请求模型；传入参数时提示正确用法。
- 在一个测试会话触发 provider 的可重试错误，自动重试耗尽后恢复服务，执行 `/retry`，确认模型继续执行、没有新增用户消息，先前已完成的工具结果保持不变。
- 保持故障再执行命令，确认下次失败仍可重试；重复提交不会对同一个等待请求执行两次。
- 等待时点击“停止”，确认 Agent 可以接收下一条正常消息，`/retry` 提示没有等待请求。
- 等待时切换 Session，确认命令只恢复当前 Session；两个 Session 同时失败时等待互不影响。
- 等待时禁用插件，确认不会卡住 Agent；检查插件管理中的图标与说明。

运行测试及实际安装由使用者完成。
