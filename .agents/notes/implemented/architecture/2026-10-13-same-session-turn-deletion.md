# Agent Note: 同会话整轮删除的持久化语义

Status: implemented

## 问题

dsh session v4 的原始事件不可重写，模型历史和聊天展示分别从日志派生。只隐藏聊天消息会留下模型上下文；直接截断 JSONL 会破坏已提交历史、存活的 Agent 状态和事件引用。用户要求删除发生在同一个聊天中，不能通过分叉替代。

## 决策

插件 lib 通过原版 `Session.append()` 追加必需的 `session/turn-deleted` 事件，携带最后一轮完整消息的原始 turn、startSeq 和 endSeq。模型消息、历史工具声明和 Conversation 组装排除该范围并重建派生数据。物理事件、聊天 ID、生命周期计数和所有非消息副作用保持原来的含义。插件通过 `runMaintenance` 持有 Agent 维护阶段直到存储 flush 完成。失败前拒绝无效目标；保存失败明确报告已经在内存提交的删除，不假装回滚。

空的拒绝轮次不遮挡上一轮消息。独立的后续上下文编辑会阻止删除，避免保留对已删节点的引用。新增事件不标记 ignorable，旧读取器拒绝它；插件读写适配使用该必需 discriminator，保留 V4。原先落在 dsh 核心中的实现现已 vendored 到插件；独立库的装载归属与兼容限制由[独立适配库记录](2026-10-14-independent-dsh-compatibility-lib.md)持有。

## 曾考虑的替代方案

**分叉到上一轮。** 能沿用公开 API，但改变聊天 ID，不满足用户要求。

**物理截断日志。** 破坏已提交代际和事件连续性，也需要同步撤销全部存活状态；不采用。

**只隐藏界面或将消息内容置空。** 前者使模型继续读取已删内容，后者无法正确移除工具配对和恢复被压缩遮蔽的旧消息；不采用。

**把删除标记为可忽略插件事件。** 旧读取器会无声地恢复已删消息，违背删除语义；不采用。

## 后果

删除可以连续执行并在重启后重放，后续请求保持同一个聊天。原始数据仍可由日志查看、导出和搜索读取；此功能不提供数据擦除，也不撤销工具副作用。删除属于低频操作，可以在该事件上重建模型和聊天投影；普通追加继续使用增量路径。V4 原生校验只存储每轮坐标，不为每轮保存整份模型历史。

本记录继续持有删除的持久化语义和被否决的替代方案；独立库只改变实现位置及装载方式，未取代这些约束。dsh 的追加日志、消息投影与不可重写代际原则继续适用，未被取代。接口、安装条件和验证入口见 [README](../../../../README.md)。
